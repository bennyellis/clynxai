BUGS FOUND AND FIXED DURING THIS WORK
  1. Installed apps never re-read the .env in their own data folder (dotenv looked in the working directory), so a key saved in Config would have been forgotten at restart.
     Fixed; also handles a variable that exists but is empty. Verified by restart tests.
  2. A phone alert with no topic set was posted to the alert server's root address with the deal's details. Fixed (nothing is sent without a topic); unit test added.
  3. With no OpenAI key every listing was skipped with "Clynx couldn't read its own analysis"; now says plainly that a key is needed, with a Dashboard notice and a Config section to add one.
  4. Scanning needed Google Chrome specifically; now Chrome, then Microsoft Edge (preinstalled on Windows 10/11); the bundled developer-only Chromium is not relied on.
  5. The packaged app could not be built reliably on Windows (tool download needs a privilege); worked around by providing the tool directory; documented.
  6. Earlier in the project: packaging previously produced a 5 GB archive of the whole project folder; now a whitelist (25 MB archive).

WHAT WAS NOT TESTED / OPEN LIMITS (also in BETA_KNOWN_ISSUES.md)
  - No clean Windows machine or virtual machine was available (Windows Sandbox/Hyper-V need administrator rights). The strongest substitute was used: the real installer, installed
    and run under throwaway profiles, with developer tools removed from the search path. A first-time install on a computer that never had development tools is therefore NOT proven.
  - The Start-menu / desktop shortcuts were checked (targets, start folder, icon) but not clicked: clicking them would have started the beta against the developer's real
    %APPDATA%\Clynx data folder, which was deliberately left alone.
  - Nothing was run against the real Facebook, real OpenAI, real eBay or real ntfy services (no keys, and nobody's account may be used). Scanning used a local imitation of Marketplace.
  - The installer is unsigned: Windows SmartScreen will warn (documented). Antivirus behaviour is untested.
  - "Install for all users" mode and a non-default install folder with spaces/unicode were not exercised beyond the temporary folder used.
  - One installed-app run once reported an uncaught-error line in the app's output; it did not reproduce in the two later full runs of that suite (one with the reduced PATH) and its text was not captured.
  - macOS: not built.
  - No long-duration (days) run.
