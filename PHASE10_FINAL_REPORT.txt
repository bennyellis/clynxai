6. THINGS I DECIDED ON MY OWN (so you can overrule them)
--------------------------------------------------------
 - Website and API share one address (simplest, safest cookies). A separate marketing domain is possible later.
 - Admin (staff) and Owner are different roles; admins cannot touch credentials or get a free plan.
 - Saved keys of existing beta testers are NEVER changed unasked; key protection is opt-in.
 - Cloud mode: if a tester already has saved keys, the app keeps using them until they pick the shared service (so nothing silently starts costing Clynx money, and nothing silently stops working).
 - Default spending limits (changeable in the console): $20/day and $200/month company-wide, $0.25/day per free customer, $3/day per Pro customer, $25/day for the Owner, 3 concurrent AI requests per customer. These are guesses to be safe, not business decisions.
 - Download analytics = one counter per release per day. No cookies besides the sign-in cookie.
 - Nunito (open license) for the website font.

While building the real-app test I let it sign in from the Electron sandbox and the app's sign-in form defaulted to http://localhost:8787 (your running dev cloud) instead of the test server, so one empty test account was registered there:
   email  desktop-1f85cd@example.com     id 0c9d266a-0ee5-4122-86a2-7785d39a7359
I fixed the cause (the form now starts from the server address saved for the installation, and the test now proves it is talking to its own throwaway server). I tried to delete the row with one narrow DELETE; the safety layer blocked a direct write to that shared database, and I did not look for a way around it. It is harmless. To remove it:
   docker exec clynx-cloud-postgres psql -U clynx -d clynx_cloud -c "DELETE FROM users WHERE id = '0c9d266a-0ee5-4122-86a2-7785d39a7359' AND email = 'desktop-1f85cd@example.com'"
Your dev containers (clynx-cloud-api/worker/postgres/redis) were not rebuilt or restarted. They run an older build without the Phase 10 routes; if you rebuild them, migrations 011-013 will be applied to that dev database.
