1. WHAT WAS BUILT (per item)
----------------------------
1  First-run checklist ("Get started", top of the Dashboard)
   Steps: Connect Facebook, Choose where to look, Add your first product, Get deal alerts on your phone (marked Recommended, skippable).
   - Each step is ticked from REAL state, not from clicks: a live Facebook login (remembered once seen), a state/city/ZIP chosen (or
     "Nationwide is fine"), something on the Search For list or in recent searches, a phone topic set (or skipped).
   - Each step explains itself in plain words and has one button: Open Facebook and log in (uses the existing login window; says the password
     goes to Facebook, never into Clynx); Choose a city or state (to Config) / Nationwide is fine; Add a product (small dialog with examples and
     an optional price limit, through the same path as the Dashboard's own Add); Set up phone alerts (the new setup dialog) / Skip for now.
   - Optional integrations (eBay, a free WatchCount login) are listed apart under "Optional extras (you can ignore these)", each marked Optional,
     and do not count toward progress.
   - Dismissible ("Hide checklist") and always reachable: a "Show the setup checklist" link on the Dashboard and a button in Config > Account.
     Steps are an ordered list, status is words (Done / To do) as well as colour, progress is a status region.
   - Existing customers are not nagged: a config saved before this existed loads with the checklist already dismissed (their settings untouched).
2  Feed cards: resale value, net proceeds, profit, margin, why
   Under the verdict chip: "Sells ~$600  Keep ~$504  Profit +$204 (41%)", a support line, and up to two short reasons.
   - Support wording follows the evidence: "Based on 8 recent eBay sales." / "Based on 4 eBay sales." / "Rough estimate: only 2 sales to go on." /
     "Rough estimate: asking prices only, no confirmed sales." / "From the reference price you set." / "No resale estimate yet: Clynx doesn't guess
     one." (no figures at all). Verified extras are mentioned. A loss shows as a negative profit. A negotiation adds "At a $400 offer: about
     +$104 profit".
   - Nothing is recomputed on screen. The gate's own numbers are now saved with its verdict (new gate_facts column; old rows read as "numbers
     weren't saved" and show no figures). Older, never-gated listings look exactly as before.
   - Cards are 20 px taller (556 to 576 high at the default width) and titles use two lines instead of three, to fit the new lines.
3  Phone alerts (ntfy) setup (Config > Notifications and the checklist)
   - Step-by-step "how to connect your phone" (install ntfy, subscribe to the topic, press test).
   - Generate private topic: "clynx-" plus 26 random characters from a cryptographic source (about 134 bits, unbiased sampling). Nothing is
     generated or changed unless the user asks. An existing topic is never replaced without a confirmation that warns the phone must
     re-subscribe; an easy-to-guess existing topic (for example the one already in use) only gets an honest warning.
   - Send test notification: sends one labelled test to the server and topic on screen (saved or not), and answers in plain words: sent / no
     topic / invalid topic / bad server address / too many messages / topic refused / can't reach the server / timed out. It validates first, so
     a typo can never become a request to another address. Copy topic button. Watches with their own topic are never touched.
4  Status and empty states
   - One status line on the Dashboard: Scanner stopped / Starting up / Scanning / Waiting for the next pass / Waiting for you to log in to
     Facebook / Scanning is failing / Facebook scanning is off / No Facebook account set up, each with the next step. It is a live region.
   - The Feed's empty state says why it is empty and offers "Go to the Dashboard" where that helps; filters with nothing to show have their own
     wording (no deals among N listings, nothing marked Worth a look, no Watch finds).
   - The Dashboard's bare "last error" line now shows a plain explanation for recognised problems (Chrome missing, connection down, timeouts).
5  The window closes from the login screen. The close request was only answered by the Config screen (mounted after login); the main process now
   lets the window close when nobody is logged in. With a user logged in the unsaved-changes guard is unchanged.
6  Database recovery failures are visible and actionable. A damaged database that cannot be moved aside (held open by antivirus, a backup tool, a
   second copy), a full disk, or a locked data folder now produce a plain-words panel on the login screen: what happened, "Nothing was deleted",
   what to try, Try again and Show data folder (role=alert). The renderer also catches a failed startup call, so it can never sit on "Loading...".

5. DEFECTS FOUND DURING THIS PHASE'S INTEGRATION RUNS (fixed, covered by tests)
-------------------------------------------------------------------------------
  1. A failed "start fresh" (database held open) used up the user's request: the marker file was deleted before the move was attempted, so the
     next try silently opened the old database. The marker now stays until the database has really been moved aside. (unit test added)
  2. A failed move also left a redundant full-size copy of the database behind each time. It is now removed (the original is still in place).
  3. On cards with long explanations the title lost its second line (squeezed by the lines below it). The title no longer shrinks and the card
     is slightly taller. The money lines also tolerate a record without the new fields (older Watch-match records).
  Also noted, not a bug: adding a product asks the app's AI helper to expand search keywords (existing behaviour of the Dashboard's Add); in
  the sandbox there is no AI so it falls back instantly.
