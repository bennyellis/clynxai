CLYNX - DESKTOP SIGN-IN "localhost:8787" FIX - REPORT
=====================================================
Rollback point: git commit 5d14b18 (before the fix). Fix: commits 16202bd and the test-log commit after it. Corrected installer: Beta 3 (0.3.0-beta.3), a signed DRAFT, NOT published.

THE SHORT VERSION
-----------------
* Port 8787 is NOT a callback listener. Clynx has no OAuth, no browser redirect and no local callback server anywhere. Sign-in is one direct request from the app to the server's /auth/login (or /auth/register). 8787 is only the address of the DEVELOPER's own Docker server on the builder's PC ("http://localhost:8787" is a development default). "localhost" always means "this computer", so on the tester's PC it pointed at nothing.
* Why it reached the tester: every build up to and including Beta 1 started the sign-in at http://localhost:8787 and wrote that value into app-settings.json as soon as the person pressed "Start Clynx". An installed copy that is updated or reinstalled keeps that file, so the old address survives and the sign-in keeps trying "this computer". The Server address box was also hidden under "Advanced" whenever an address was already saved, so the tester could not see or change it.
* Fixed in Beta 3: (1) an installed build treats the old developer value as "no server chosen" and replaces it; (2) the build carries the real address, https://ben.tail0e333d.ts.net, so a new PC starts there; (3) the Server address is always visible on the sign-in form and is tested automatically before any password is typed; (4) if an address says "localhost" and nothing answers, the message now says so in plain words. Nothing about authentication was loosened.
* Tested with the packaged app, 24 of 24 checks pass, including a real "Test connection" to https://ben.tail0e333d.ts.net (real certificate, private mode noticed) and a proof that nothing reached the developer server on localhost:8787.
* Beta 3 is on your server as a DRAFT (signed, hash verified). You decide when to publish.

1. COMPLETE DESKTOP LOGIN FLOW (as implemented)
-----------------------------------------------
 Renderer LoginScreen.tsx -> IPC auth:login / auth:register -> main/cloudClient.ts -> HTTPS POST {server}/auth/login | /auth/register (+ invitation code when the server is private)
   -> server returns a 15-minute access token + a rotating, device-bound refresh token -> stored in cloud-session.json (encrypted when the OS allows) -> device registration -> automatic sign-in on restart.
 {server} = the "Server address" box, saved in app-settings.json (cloudApiUrl). Address rules (serverAddress.ts): https required for internet hosts; plain http only for loopback / private network / .local / single-word hosts.
 No redirects, no callback URL, no listener on any port, no browser involved in desktop sign-in (the website uses its own cookie sign-in; that is separate).
 Where 8787 appeared: exactly one place in src (main/index.ts defaultCloudApiUrl: used only when the app is NOT packaged, i.e. a developer run) plus the settings value Beta 1 saved.

2. ROOT CAUSE
-------------
 Beta 1 default = http://localhost:8787, saved to app-settings.json on first use; the box was hidden under "Advanced" once something was saved; Beta 2 removed the default for NEW installs but kept any saved value, so an upgraded or previously used profile kept localhost. On another computer "localhost" is that computer, nothing listens, the request fails.
